# Seeded demo and testing workflows

[Back to README](../README.md) · [Backend](backend.md#two-libraries-yours-and-the-demo) · [Development](development.md)

The demo lets you try every screen without an account or a paid request. It is a second library on the server, with the same routes and the same queue as yours and a database of its own, seeded with four books in every state worth seeing. Every endpoint in it is answered by the server itself. Sample counts below describe the seeded states, not promises about every book.

## Demo tools

The header's **Demo** chip opens the demo drawer. **Enter demo** reloads the tab into the demo library and **Leave demo** reloads it back to yours. The choice lasts for the tab's session, so a new tab opens on your library. There is one demo library, shared by every tab that has it open, and it keeps what you do in it until it is reset. The demo needs the server as much as your library does: a server that is not running is shown as exactly that on the Library, and neither library ever stands in for the other.

Nothing in the demo is sent to a provider or billed. Every endpoint is **simulated**: its base URL is `simulated://` in front of the host it imitates, and the server answers it with a quiet tone per line or a script read from the prose, at the endpoint's latency and fail rate. Everything else is real. Jobs run on the server's queue, clips are audio files (made the first time something plays or builds them), and audiobooks are files on disk. Costs are worked out from each endpoint's rate card, so budgets and estimates behave as they would, and every request is marked simulated. The sidebar says so under the app name. The demo's provider names and rates are examples, not current pricing.

The drawer stays open while the page reacts. From top to bottom it shows:

- the situation the demo is in now: what applying it did, in counts, and the steps worth trying;
- every situation, grouped;
- the **speed** of simulated work (1×, 4× or 16×), which divides every simulated wait on the server; the latency a request records is still the time it really took;
- **Reset**, which says how many runs in flight it will drop, and **Leave demo**.

The chip carries the name of the applied situation, so you can read it with the drawer closed.

## Situations

A situation puts the book, its script, its cast, the queue, the endpoints and the exports into one state together, and opens the page it is about. The server rebuilds the demo from its seed every time, so picking the same row twice, or three others in between, gives the same situation. What a situation has running as you arrive is running for real: chapters scripting or narrating on the simulated endpoints, a build part way, an endpoint still cooling down after a 429. **Reset** puts the seed back, with a few chapters scripting and narrating so the queue is not empty the first time you look.

A situation or a reset drops the work in flight: the demo's queue is stopped, the running job is aborted and waited for, and every row and file of the old state is removed before the new one is written, so nothing from the state you left can land in the one you are looking at. The page then reloads onto where the situation opens, so half-typed forms and page filters start afresh; a page open on a book the demo no longer has (one you added yourself) goes to the Library.

## Things to try

- **Importing:** in the **Demo** drawer pick **A long serial with scattered updates** under Importing an EPUB. Skip the release schedules with the group's **Skip 2**, press **Skip all 10 suggested**, `⌘Z` it back; open **Needs review** and read _The Widow's Percentage, Revisited_ — the note at the end is marked — then **Keep chapter**. **Add to library · 202 chapters** lands on the overview, where Scripting counts 202 and the picker's "10 skipped" links back here. Try **An EPUB that is nothing but notices** for the all-skipped state, and **A clean novel** for the one-click add.
- **Scripting:** _The Cliché Cultivation World_ has three volumes — collapse them in the chapter list. Tick unscripted chapters on _Letters from the Drowned City_ and run; new chapters sometimes surface an alias (dashed "new") — the chip opens the Cast page, where merging lives. The cast rail sets each speaker's voice where you are reading them; hide it with its own button, the Cast button or `c`, and change type with `Aa`.
- **Narration:** _Cliché_ ch 4 is partly failed — retry from the ledger. The Narrator sits on the free local Kokoro (limit 500 chars) and dialogue on OpenAI; narrate ch 7 and watch rows split into parts. On _Drowned City_, Old Tobiah's voice lives on the paused Azure proxy — resume it or repick. On the Endpoints page, **Fetch from server** on an endpoint's Voices tab pulls its voice list.
- **Export:** pick an Export situation. _A long book_ opens **Thousand Gates of the Ninth Heaven** — 214 chapters over 6 volumes: filter to **Needs attention**, switch **Files** between one file / per volume / per chapter and watch the names and the count follow, then **See the chapter order**. _An export that needs updating_ shows v2 nine chapters behind with 191 carried over — press **Update to v3** and watch the Queue say `Encoding 50 of 204 · file 2 of 6`. On _Ashes of the Starforge_ chapter 1 is stale, so the build waits for you to choose. Open **Loudness** to see the target each file is levelled to; open **Pauses** and nudge "after a line" — the running time, the size and the preview all move, and the finished export says it is behind the book. Pick _Running, failed and finished builds_ for a build still going, one that failed while writing a file — **Retry** builds it again — and one finished.
- **Script history:** pick _A chapter with a script history_. The reader opens on **History**: four entries, newest first. **Preview** “Before trying DeepSeek” — read-only, the current script untouched — then **Compare with current**: read the summary before the detail, filter to _Speakers_ or _Split, joined, new, gone_, and **Open the line** to land on it in the reader. **Restore…** counts what comes back before you press it — six clips match again, one of them recovered from the paragraph the re-script cut in two — and the chapter goes from stale to done; `⌘Z` puts the re-script back. Restore v1 instead to see the warning about a speaker the cast no longer has. Then edit a few lines yourself and watch them collect as one “N manual edits” entry.
- **Site text:** open _Cliché_ ch 8 on Scripting, or pick **Site text and a translator's note**. Three lines are marked as site text, one of them a sentence cut in three around an anti-scraping line, one is a translator's note, and the detector has two suggestions: accept the one on “Updated first on wuxiabox.com” and set the library-pavilion line back to narration. Narrate the chapter and the site text is skipped and counted; turn on **Read translator's notes aloud** on the overview and the note becomes a line to narrate. Re-script it on the simulated endpoint and the boilerplate comes back marked, every word still matching the text ([site text](scripting.md#site-text-and-translators-notes)).
- **Review:** _Starforge_ ch 1 has three flagged clips and one retake already waiting — play both takes and keep one. Flag another line yourself (⚑), then `↻ Retake flagged`.
- **Pronunciation:** Narration → **Pronunciation** on _Cliché_ — `Ji Ning → Jee Ning` and `Lan’er → Lahn-urr` are already in; click the count for a before/after on a real line, change one and watch the clips that used it go stale. In the reader those words are underlined; hover for the respelling.
- **Pacing:** _Starforge_ ch 1 holds 1.5s after the Captain's threat and runs straight on into the reply — the ledger's scrubber draws both gaps. Set your own in the reader under **Pause after**, or `[`/`]`.
- **Endpoints:** open **Endpoints** in the rail. _Antigravity (local)_ has never been used — it reads **Not tested**, not healthy. The five speech endpoints bill five different ways on purpose: _OpenAI (main)_ per 1M characters, _Fish Audio_ per 1M **UTF-8 bytes**, _Gemini 3.1 Flash TTS_ at separate rates for input text tokens and output audio tokens, _Local Kokoro_ at **zero** (free, which is not the same as unknown), and _Azure proxy_ per audio minute at a rate nobody wrote down: its spend shows **unknown**, and the totals say how many rows they are missing. On the Overview tab switch to **Latency** and see queue wait stacked under provider response, then click a bar to filter the Activity list to those requests. Type `2500` into Concurrency on the Requests tab — the slider range follows. Start a narration run, then **Pause** _Local Kokoro_: the queue holds, the run doesn't fail, and **Resume** picks it up. **Cancel** says what it will do first.
- **Boundaries:** in the reader, open a line and press `s` — click a gap to cut it, then give the second half its own speaker. `m` joins a line with the next. Try it on the unverified chunk in _Cliché_ ch 7.
- **Bulk corrections:** pick _One speaker mis-attributed all through_; Search opens on the alias. Tick a chapter, or **Select all matching results** (it takes the matches the page is not showing), then **Change speaker…** → _Ji Ning_: 46 will change, 21 already use it, 12 clips go stale. Apply, read the strip, **Undo this batch**. Pick _Ning_ instead to see the no-voice warning, try **Direction…** with an empty field, and search `Ji Ning` for lines already read by him — a batch with nothing to do. **Add pronunciation…** with `Ji Ning` in the box finds the entry that already exists.

## How the demo is built

The demo is the server's second library, under `/demo/api` with its own database (`data/demo.db`) and folders (`data/demo/`); see [two libraries](backend.md#two-libraries-yours-and-the-demo) for how it is kept apart from yours. A demo tab is the same page talking to that base instead of `/api` ([src/services/mode.ts](../src/services/mode.ts)): no store has a demo branch of its own, and nothing in the browser simulates anything.

What it is seeded with is the world in [server/demo/seed/](../server/demo/seed/) — the books, casts, scripts, clips, exports and endpoints in `fixtures/` and `world/`, and the situations in `scenarios/` — written by [server/demo/world.ts](../server/demo/world.ts), with each situation applied to it in memory before it is written ([server/demo/situations.ts](../server/demo/situations.ts)) and what it has running made real once the queue starts ([server/demo/live.ts](../server/demo/live.ts)). The rules it keeps:

- The same screens, with seeded books, scripts, cast and endpoints, without provider credentials or a paid request; costs labelled simulated and a clear Demo indicator.
- The choice made at the service boundary as the page loads, never a view's own branch, and never a silent fall back from one library to the other.
- Demo data separate from your library and your keys: a reset or a situation rebuilds the demo and drops its work in flight, and never touches your library.
- Repeatable situations for success, partial failure, rate limits, missing voices, budget limits, stale audio and export retries.
- Integration tests on a private library with the server's fakes in place of the providers; the page's stores are tested against a seeded demo library in-process ([tests/support/demoServer.ts](../tests/support/demoServer.ts)). Real provider checks remain an explicit, small test (`pnpm test:live`).

One place the seed and an import differ in shape: an import stores a chapter as Markdown — the headings, emphasis and tables the EPUB laid out — while the seeded prose is plain. [MarkdownText.vue](../src/components/MarkdownText.vue) draws both through one path, because plain prose _is_ Markdown: paragraphs split on the blank line, and nothing the seeded prose contains means anything else. Where it would mean something, the Markdown reading is the one you want — a `* * *` scene break becomes a rule the narration drops, rather than three asterisks handed to a speech provider.
