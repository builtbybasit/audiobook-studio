# Export planning and updates

[Back to README](../README.md) · [Demo scenarios](demo.md) · [Pacing and playback](audio.md)

A build is a job on the server that stitches the chapters' clips into files on disk, with the book's pacing inside each chapter and the export's gap between two, and hands them back as downloads — in the demo as in your library. The page plans it and the server builds exactly that plan. [Backend](backend.md#export) has how the server does it.

## Building and maintaining an audiobook

A 200-chapter serial is the case the page is built for, so it is two jobs on two tabs: **Build** (what goes in, what comes out) and **Audiobooks** (what you have made, and whether it still matches the book).

**One plan, one truth.** [src/lib/exports.ts](../src/lib/exports.ts) is pure: given the selected chapters, the volumes and the settings, `planOf` returns every output file with its chapters, running time, size and marker count. The file count, the example names, the chapter order, the duration and the size are all read off that one structure, so they cannot drift apart from each other or from the selection, and the server writes the files the plan names rather than deriving them again.

**An export is the deliverable, not a file.** Format (M4B or MP3) and layout (one file · one per volume · one per chapter) are independent: layout decides how many files and nothing else. One export entry holds `files[]` — "one audiobook in 6 files" rather than six entries to keep in sync. A set of files is named by its folder, a single file by itself. MP3 says plainly that it has no chapter marks every player reads, and offers the two ways out (one file per chapter, or M4B) instead of a disabled checkbox.

**Selection is the contract.** `ExportChapterList` lets you tick _any_ chapter, including ones that cannot be exported, because a chapter silently left out is the failure this page exists to avoid. Each row says what is wrong with it — `no audio`, `failed`, `partial`, `stale`, `running` — and the plan panel turns the totals into things to do: **Narrate them**, **Leave them out**, **Use the audio as it is**. "Leave them out" unticks them, so the list and the build stay the same set. The build refuses rather than trims: `reviewOf` is what the server asks too, so a chapter with no usable audio, one still being narrated, or a stale one without _use stale audio_ comes back as the blocker's own title and detail, and nothing is queued. At 214 chapters the list has search, per-volume select and collapse, a jump box, shift-range selection, `↑↓`/`space`/`/`, and a **Needs attention** filter that doubles as navigation, with a warning in the footer when the filter hides ticked chapters.

**Using stale audio is a decision.** `useStale` starts false, so a build containing clips the script has moved under is always something someone chose: the blocker offers re-narrating, leaving them out or using them, and once accepted the plan says so in amber with a one-click undo of the choice.

**What is not read is not stitched.** A line of site text, or a note the book does not read, is left out of the stitch whether it has a clip or not (`heardLines` in [src/lib/siteText.ts](../src/lib/siteText.ts)). The plan's running time and size, the preview and the build all leave it out, so they agree. The chapter's fingerprint covers only the clips that are heard, so marking a rendered line as site text, or turning the book's notes on or off, shows a finished export as behind the book. A chapter whose only lines without audio are lines it does not read is ready to export, and its script and ledger count those lines as skipped rather than missing ([what is read aloud](audio.md#what-is-read-aloud)).

**Pacing has one owner.** Gaps _inside_ a chapter belong to the book's pacing and its per-line overrides — the numbers the reader, the ledger, `chapter.duration` and the player share — and Export edits them through the same `setPacing` action rather than a copy. Export owns exactly one gap, **between two chapters**, because that join does not exist until they are stitched. `durationOf` is the only place chapter time is added up, so the plan, the size estimate and the preview agree, and the chapter fingerprint covers the stitched silence, so changing a pause marks a finished export out of date even though it re-renders nothing.

**Loudness.** A book read by several voices from several providers arrives at several levels, and a listener reaches for the volume knob long before noticing the bitrate. The Loudness section is on by default at −18 LUFS, with −23 (EBU R128) and −16 (podcast-loud) offered. It says what the build will do and shows no level of its own: a level is only known once the audio has been read, and the page reads none. The build is what measures and corrects loudness, and only under ffmpeg (see [encoders](#encoders-and-formats)): each file it writes is measured over its stitched audio and brought to the target with one gain, so two voices that differ from each other still differ inside the file. The job's log records what each file measured before levelling (`Moonlight Ledger.m4b is written · loudness −21.4 LUFS in, levelled to −18`), which is where a finished build's figure lives.

**Listening and downloading.** **Preview** and each planned file's ▶ play the real clips on the app's [one player](audio.md#one-player-across-the-app), with the book's pacing inside a chapter and the export's gap between two. On the Audiobooks tab, **Listen** plays a finished version _as it was built_, from the timeline it recorded, so a correction made since is heard as a difference; it runs that timeline without the file, so the bar says "timed, not heard". **Download** fetches what the build wrote, one download per file, under the name the server gave it — the encoder decides the extension.

**Builds are jobs.** One build is one job, whatever it produces, so a 200-track export does not put 200 rows in the Queue. The job carries an `exportRun` — settings, chapters, which file is being written, how many chapters were encoded and how many carried over — which the Queue's running row, the job's run details and Retry all read. A book builds one audiobook at a time, because a second build would read the clips the first may be replacing; a second press is refused, naming the one that is going. Cancel removes the version being written and leaves the one on disk alone; a failed build does the same and says so (`v3 is untouched and still the audiobook on disk`), with Retry from Export, the toast or the Queue.

**Updating instead of rebuilding.** Every export stores a fingerprint per chapter (`chapterSignature`: the clips, the stitched silence and the chapter's narration state). "Needs an update" is a real comparison against the book as it stands: _9 chapters narrated since · 4 changed · 1 no longer has audio · 191 of its 196 chapters are unchanged and would be carried over rather than encoded again._ **Update to v3** encodes only what moved and copies the rest (`reusedChapters`, the same function the build uses), the job's log says which is which, and the version on disk stays current until the new one lands. Changing an output setting (bitrate, layout, loudness target…) makes a different file, so nothing is carried over, and the page says that too.

## Encoders and formats

What a build writes depends on the encoder the server was started with, and the page cannot tell which, so it says what each one writes under the Build button.

- **`EXPORT_ENCODER=wav`** (the default) needs nothing installed. It stitches the clips into one real, playable WAV per output file. It is not an M4B and writes no chapter marks, cover or tags, so rather than name a file `.m4b` that is not one it writes `.wav` and says all of that in the job's log. It applies no loudness correction. Carrying over is literal: an unchanged chapter's bytes are copied out of the version on disk.
- **`EXPORT_ENCODER=ffmpeg`** writes the format the settings asked for — AAC in an M4B with chapter marks a player reads, or an MP3 — with the cover and the book's details as tags, and measures and corrects loudness to the target in two EBU R128 passes. A span of AAC cannot be spliced beside audio encoded in the same run, so an update re-encodes every chapter instead of carrying unchanged ones over, and says so. A server configured for ffmpeg with none on `PATH` refuses to start.
- **Clips narrated in MP3 or Opus need ffmpeg.** The stitcher joins WAV and nothing else, so a book with an MP3 or Opus clip in it is refused before anything is written, naming the chapter and the two ways out: restart with `EXPORT_ENCODER=ffmpeg`, or narrate again with the endpoint set to WAV. ffmpeg decodes each such clip, so a book narrated partly in one format and partly in another builds as one.
- **One sample rate per file**, under either encoder: a build that would mix rates is refused naming the chapter that brought the second one (Opus counts as the 48 kHz it decodes at).

In the demo, the **Export** group of situations covers a book ready to export, ready / missing / stale together, the 214-chapter serial, an export that needs updating, and running / failed / finished builds, where a failed one waits for **Retry**; a situation or Reset drops the work in flight ([demo tools](demo.md#demo-tools)).
